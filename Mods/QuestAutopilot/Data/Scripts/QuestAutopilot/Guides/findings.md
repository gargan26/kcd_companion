## The mod's Lua

- **No `io`.** A mod's Lua has `os` (`clock`, `time`, `date`) but no `io` table, and no `os.execute`, `os.getenv` or `os.rename` either (the `os` functions kcd-cheat's table dump lists exist only in another context). A file written by the mod is impossible; `st_graph <quest> log` cannot write its file.
- **`QuestSystem` takes a quest's name with its exact capitals.** With `q_millerDate` started and its `visitTerezaFirstTime` completed, `IsQuestStarted("q_millerdate")` and `IsObjectiveCompleted("q_millerdate", "visitTerezaFirstTime")` both answer false (2026-10-16). A name a player types goes through the quest table first (`st_graph:find_quest`, which ignores case).
- **`loadfile` and `dofile` read loose files from disk**, relative to the game folder, while `System.LoadTextFile` sees only paks (a loose file reads as nil) and `System.IsFileExist` answers 0 for one. A Lua file dropped in the game folder is the way into a running mod; `dofile` also reloads changed mod code without a restart.
- **`System.LogAlways` writes one log entry per call, the line break in front of it** (`\r\n<text>`; the file never ends with a newline). It strips `$<digit>` as a colour code, passes `%` through, keeps UTF-8, and cuts an entry at about 3,900 bytes. The console's `exec <file>` runs a loose `.cfg` of console lines (`#<lua>` included).
- **Script timers set while the mod loads do not survive the level load**, and the mod's scripts do not run on the Game Over screen. A `UIAction.RegisterActionListener` call sees `sys_loadingimagescreen` `OnEnd` when a level has loaded (kcd-cheat starts its timer there).
- **`Statistics.Set` / `Increment` reach only the game's Script and Quest statistics** (`ScriptStory…`, `TournamentsWon`): the game's own scripts use them on nothing else. Raising `AnimalsKilled` by 50 changed nothing, and setting `ScriptMasterOfArena` to 1 did not award Arena Master, even after a save. Achievements cannot be earned through their statistics from Lua.
- **An item's condition is a copy.** `ItemManager.GetItem(id).health = 1` does not change the item, and `ItemManager` has no setter (`AddOnEquipBuff CreateItem GetItem GetItemName GetItemOwner GetItemUIName IsItemOversized RemoveItem SetItemOwner`). KCD2 Companion's *Gear never wears* has no KCD1 form.
- **Saving**: `Game.SaveGameViaResting()` writes `autosaveNNN.whs` at once when the game allows a save and nothing while it holds a save lock (both seen the same evening); `Game.QuickSave()` returned false in both states. `Game` also has `AddSaveLock` / `RemoveSaveLock`.
- **Money**: `player.inventory:GetMoney()` returns groschen (with a fraction); the money item `5ef63059-…` counts tenths, so `+1000` groschen is `CreateItem(id, 1, 10000)`; `Utils.RemoveInvItem(player, id, tenths, false)` takes it away.
- **Mounting**: `player.human:ForceMount(horse.id)` mounts Henry; `ForceDismount()` gets him off. The first mount of a playthrough opens a Horse-riding card that pauses the game (and the mod) until Esc is held.
- **Rays and heights** (2026-10-20): a `Physics.RayWorldIntersection` hit carries `pos`, `normal`, `dist` and `surface` (the material: terrain 128, a hut roof 122, a stream-bank mesh 132), and a ray meets a face from behind as well, with the face's own normal: a ray down from inside a floor slab meets its underside at normal.z −1. `ent_all` = 287, `ent_living` = 8, `ent_terrain` = 256, `ent_static` = 1; `ent_water` does not exist. `System.GetTerrainElevation` takes a vector (`{x, y, z}`); called as `(x, y)`, as Quest Autopilot's `st_teleport` does, it returns nil. `CryAction.GetWaterInfo({x, y, z})` returns the water's surface for a point in water (the Sázava at Sasau: 17.44 over a bed at 16.10) and −1e6 on dry ground; `AI.IsPointInWaterRegion` returns the depth.
- **Trees' solid parts load only near Henry**: a line through a spruce in Rattay Woods met its trunk at 6.4 m from beside it and nothing from 1.2 km away, while buildings, rocks and bridges read the same from afar.
- **The main menu has a player entity** (at 728, 3411 on `rataje`), so `player ~= nil` does not mean a save is loaded.

## Data

- **Journal lines**: an objective's journal name is `skald/skald_objective.xml` (quest, objective → skald element) → `skald_objective_string.xml` (type 1, name) → a key in `text_ui_quest.xml`: 2,121 objectives in 161 quests. The objective names in `quest_objective.xml` are code names (`speakWithFather` → "Go to your father").
- **Achievements**: Steam's API names are `achievement.xml`'s `achievement_name` (82). Their names and descriptions are not in the game's text tables; Steam supplies them in its own language. `achievement_rule.xml` ties each to a statistic and threshold, and `quest/quest_reward_achievement.xml` ties 56 to the quests whose objectives raise that statistic.
- **Levels**: the world data spans `rataje` (the map) and `rataje_dlc4` (A Woman's Lot's prologue, the same terrain coordinates); every record carries its level and the tabs show the loaded one (`sv_map`).
- **Places**: KCD1's layer names are flat, so places come from the location areas (`SmartAreaShape` with `guidLocationId`). The median of an area's entities can fall indoors: "Rattay (centre)" put Henry inside a house. 15 places have a fast-travel point tied to their location, where the game's own fast travel lands, and use it.
- **Shops** have no inventory-preset link: stock comes from `shop_type2item.xml` by shop type.
- **Trigger volumes cover the whole map** (`rataje` level.pak, 2026-10-20): 1,110 `TriggerArea` entities carry a polygon (`<Area Height=…><Points>`, points relative to the entity's `Pos`; 72 are rotated). `globalTriggerArea` spans 4,091 m, and every one of the 47 places' landing points and all seventeen of kcd-cheat's safe towns lie inside it and usually inside quest ones too (`q_plagueInMerhojed_illlness` holds Merhojed's, `ta_conquest_gameover` Talmberg's). Being inside a trigger volume is therefore no test of a safe landing; the crash in `../learnings.md` came from jumping to a quest destination that is itself a trigger entity, which the trainer snaps to a town.
- **The terrain** is 4,096 × 4,096 m from 0 on both levels (`levelinfo.xml`: `TerrainInfo HeightmapSize="4096" UnitSize="1"`).
- **Item figures as the inventory shows them** (measured against the game's item info, 2026-10-14): a melee weapon's damage is `melee_weapon.attack` × its stab, slash or blunt modifier × 10 and its defence `weapon.defense` × 10; armour's stab, slash and blunt defence are `armor.*_def` × 10 and its noise `armor.noise` × 100; a bow's power, strength needed and charisma are the table values; prices are `pickable_item.price` ÷ 10 in groschen. Daggers carry no damage or defence at all.
- **Item groups**: an armour piece's slot comes from its clothing (`armor.clothing_id` → `clothing.armor_archetype_id` → `armor_archetype2body_subpart` → body subpart and layer → `equipment_slot`, exclusive subparts weighted); horse gear by `armor_type` 10-12. A potion's purpose comes from the buff it gives (`consumable_item.buff_id` → `buff.buff_class_id` and `params`: `health+30/t` heals, `str+5` boosts, `health-110/t` poisons). Skill books are `document_required_skill.xml` rows (skill, level needed, XP). A house key's internal name says whose it is: `vk_key_<village>_<house>_<doors|chests>`, the village as the code the places carry.
- **The ending catalogue's English has slips** (`Data/st_outcomes.lua`, generated in May; the Chinese translation of 2026-10-13 corrected them in Chinese only): several Theresa-prologue endings (`q_theresa_blanka`, `_brother`, `_escape`, `_johanka`, `_return`, `_silver`) say Henry where the player is Theresa; `q_auschitz` says "reports to Ledecko" for learning about Reeky in Ledetchko; "neckles" for the cross; `q_returnToSkalitz` treats Prcek as Runt's man when the data makes him Runt; `q_inVinoVeritas` names the wagoner "Carter"; `q_package` says "Pesek's miller" (Peshek is the miller); `q_pribyslav` contradicts itself; `q_gallowsBrothers` calls Andrew, Matthew and Fritz brothers; `q_pribBattle` has Istvan watching the reclaimed settlement. About 60 descriptions narrate engine internals (watchdogs, flags, the behaviour tree).

## Quest skip side effects

Read from the game data on 2026-10-18 (retail 1.9.8) by `tools/extract_skip_effects.py`; per-objective results in `reference_data/skip_effects.json`. Static reading only: nothing here was run in the game.

**What the trainer's completion does.** Advance, Complete, Force and the ending runs all end in `QuestSystem.CompleteObjective(quest, objective, true)` (`st_navigator:safe_advance`, `st_cmd:run_outcome`); Skip to next decision completes nothing (rolled back in May). The engine then does what belongs to the objective itself: it starts the objective's enabled `quest_transition` successors, pays its `quest_reward_*` rewards, and tells the quest behaviour trees, whose handlers on "<objective> Completed" run. What play does besides, at the moment it completes the objective, is missed.

**Where KCD's quest logic lives.** Five places complete an objective in play:

- *Conversations*, in `Tables.pak` `Libs/Tables/text/`: a dialogue sequence carries `sequence2quest_objective` rows (action 1 start, 2 complete, 3 cancel, in `order_by` order, each with a condition such as `IsObjectiveStarted('q_skalitz','beerWasBad')`) and a `sequence.script` (Lua run as the sequence plays: items, global and dialogue-local variables, recipes, messages). `sequence.reputation` is a reputation change with the speaker (`rpg/reputation_change.xml`). A script calling `QuestSystem.OpenInventory(quest, npc, objective)` opens the hand-over screen, and the hand-over completes the objective.
- *Behaviour trees*, `Scripts*.pak` `Libs/AI/quests/<quest>.xml` (plus `Libs/AI/final/` for shared behaviours): a `SetQuestObjective` or `SetQuest` node with `function="CompleteObjective"` inside a `Sequence`. Only each `BehaviorTree`'s `Root` runs; its `ForestContainer` holds unconnected editor islands (q_sikBas's whole `update` logic sits there, its `Root` a lone `Wait`). Quest attribute `""`, `$this.name` or `$__object.name` means the file's own quest.
- *The engine, from `quest_objective.condition`*: `"1"` completes the objective once it has started and what it tracks (`quest_tracked_asset` → `quest_item` / `quest_place` / `quest_npc` / `quest_statistic`) is satisfied: the items held, the place or person reached, a statistic; with nothing tracked, at once (3,088 objectives: autosaves, `endQuest`, log lines). An expression completes it when it holds (`takeNailsFromChest`: `IsObjectiveCompleted('q_skalitz','takeNailsFromChestTracking')`). `""` and `"0"` leave it to a conversation, a tree or a script. Read from the data: of the 3,838 objectives with condition `1` in the quests below, 3,088 track nothing, and for 3,000 of those nothing else completes them.
- *Timers*: `quest_objective.autocomplete_timeout_str` (`"4m #GT"`; `-1` is none).
- *Lua scripts* (`Scripts/Quests/*.lua`, the DLC4 Revelation scripts): a dozen calls, mostly debug.

The quest flowgraphs (`GameData.pak` `Libs/quests/flowgraphs/`, patched by `ipl_patch_010800.pak`) are the same objectives, transitions, tracked assets and rewards as the tables; the developers' Haste jump-to commands (`Scripts/Libs/Haste/haste.xml`) set objective states directly too.

**What a tree's completion runs with it.** The tool walks up from the completing node through its enclosing `Sequence`s: the effect nodes before it back to the waiting node that starts it (a gate, a wait, a message read, a dialogue, a cutscene, a movement) and after it up to the next waiting node all run at that moment; a gate around it is what starts it; a `Parallel` that succeeds on its first child lets what follows it run too. From `q_conquest.xml`, *Ride with Sir Hans to meet your father*:

```xml
<AreaPresence NPCs="__player" Area="chase_final" TrackIn="true" Once="true" …>
  <Sequence>
    <ExecuteSoundTrigger entity="this.id" triggerName="music_battle_off" />
    <InstantSendMessageToNPC target="__player" type="trespass:expected" values="entity($t_actors['ptacek']), set(true), source($this.id)" />
    <SetQuestObjective quest="q_conquest" objective="chase" function="CompleteObjective" />
```

Play: Henry reaches the chase's end and the tree tells the trespass system Ptacek may be there, then completes the objective. A skip completes it and sends nothing.

**What the trainer does with it** (1.2.0). The extractor also writes `src/Scripts/QuestAutopilot/Data/st_skip.lua`: for every objective of every shipped quest that is not safe, its verdict, the kinds missed and what to fire. `st_skip.lua` completes an objective through it, for Advance, Complete, Force, the ending runs and `st_advance`:

- *safe*: `CompleteObjective`, as before.
- *replayable*: the steps of the way that completes or cancels the fewest other objectives, a conversation first: its Henry-side script lines (`Utils.GiveItem` from or to Henry becomes a give or a take; money in groschen; other lines run as written), then its objective rows in `order_by` order, each under its condition (read with `QuestSystem`, `Variables.GetGlobal`, and "started" counting a completed or cancelled objective, so nothing finished starts again). A tree's stretch replays its effects before the completion, the completion, then those after. A step that fails is logged and the objective completed anyway.
- *give_items*: gives what Henry lacks of the tracked items and waits 1.5 s for the engine; if the objective has not completed then, it completes it directly and says so.
- *upstream*: completes (through the same path) or starts the objective the tree reacts to, waits 1.5 s, and completes the target directly if the tree did not.
- *needs_world* and *unknown*: the button reads *Advance (risky)* (*Complete*, *Force* alike), its tip says what play does more, and, while the play option *Warn before a skip that can leave a quest stuck* is on, both faces ask first with *Skip anyway*, *Cancel* and *Don't remind me again* (KCD2 Companion's wording and its confirm box). Play options outlive the game: the plugin keeps each `opt` call in `quest_autopilot_bridge\prefs.lua`, which the mod reads with `loadfile` at start.
- *never*: no Advance, Complete or Force.
- Ending runs complete their steps one at a time through the same path (waiting for items and fired objectives to settle), pass over steps the game never completes or the quest does not have, and stop at the first risky one: 287 of the 506 catalogued endings run to the end.

## Mod loading

- **A first launch moves `Mods\` aside.** With no `mod_status.xml` in the game folder, KCD 1.9.8 assumes an update from an older version, renames `Mods\` to `mods_old\` and writes `mod_status.xml`. Seen on a fresh Steam install; a player who has run the game before is not affected.
- **`Mods\mod_order.txt` turns the mod list into an allow-list.** When the file exists, KCD loads only the mod folders it names, one per line, in that order (`kcd.log`: "Loading mods from mods/mod_order.txt"); without it, every folder in `Mods\` loads alphabetically ("mods/mod_order.txt not found"). Vortex writes the file on every deploy: its own enabled mods, plus any line already there that names a mod folder present in `Mods\`. A mod someone extracts by hand into a Vortex-managed game is therefore never loaded until a line names it, and once named it stays. The plugin adds `QuestAutopilot` at its start, before the engine reads the file (`WHGame.dll` imports `dinput8.dll`, so the ASI loader and the plugin load ahead of the engine's own start). Strings in `WHGame.dll` 1.9.8, Vortex's KCD extension (`game-kingdomcome-deliverance`), and a player's report, 2026-10-16.
- **The Epic build keeps `KingdomCome.exe` in `bin\Win64MasterMasterEpicPGO`**, not `Bin\Win64` (an Epic player's `kcd.log`: build 1.9.4.0 of February 2020, working folder the game folder, "Mods dir is 'mods'"); Vortex's KCD extension looks for `Bin/Win64/KingdomCome.exe` and missed it, and its forum workaround copies the folder to `Win64`. KCD2 on Epic uses the same folder name, so the exe's folder alone does not tell the two games apart; `Data\Levels\rataje` does. Forum threads t/67604 and t/68209 on forum.kingdomcomerpg.com, 2020.
- **`kcd_launcher.log` in the game folder records how far a start got**, rewritten each start: "Creating splash...", the DLLs from `Bin\Win64Shared`, "Loading Game DLL 'WHGame' ...", "Game DLL is loaded", "Initializing the game...", "The game is initialized", "Destroying the splash...", "Run: begin". A start that dies at the splash stops before the last of them; `kcd.log` then shows the engine's own steps and `Bin\Win64\questnative.log` the plugin's (2026-10-20).
- **A `user.cfg` mod installed through Vortex lands in `Mods\<folder>\`**, where the game reads "mods/<folder>/mod.manifest not found" and never reads the file, though Vortex lists the folder in `mod_order.txt` (Texture streaming improvements #27 and More Responsive Targeting #83, 2026-10-20).
- A manifest `<modid>` with capitals draws "invalid ModId. ModId accepts only lowercase letters and underscore" and loads anyway; KCD Companion's is `questautopilot`.
- Mods' table patches `Libs/Tables/rpg/buff__<name>.xml` merge into the buff table (kcd-cheat's `buff__cheat.xml`, and KCD Companion's buffs: `imm`, `rms*2`, `cap+1000`, `xpm*3`, `con`/`evi`/`noi` read back through `GetDerivedStat` as set; `wat` is not a derived stat and does not read back).

## Steam

- **`steam_api64.dll` is an old SDK** (121,768 bytes): no flat C API, one interface string, `STEAMUSERSTATS_INTERFACE_VERSION011`. `SteamUserStats()` returns the interface; its slots are SetAchievement 7, GetAchievementAndUnlockTime 9, StoreStats 10, GetAchievementDisplayAttribute 12, GetNumAchievements 14, GetAchievementName 15 (the SDK header's order; MSVC swaps each GetStat/SetStat overload pair within slots 1-4). Steam listed 82 and the earned count matched Steam's library page.
- **Storing an achievement from outside the game crashes it.** Steam's "stats stored" reply reaches the game's reward code (`g:\workspace\kcdx_0109\code\cryengine\crynetwork\lobby\steam\crysteamreward.cpp`), which takes it for the end of an award task of its own. With none pending, the current-task slot is −1, and the task end (WHGame+0xb16550, called from +0xb16a30 with the slot at +0xb0) reads `[this + slot*48 + 0x1e4]`: an access violation two seconds after the store. The award itself is kept: Alcoholic stayed on Steam. The task slots are eight entries of 0x30 bytes from +0x1d8 (the timeout loop at +0xb17a70 walks 0-7). Dropping a task end whose slot is outside 0-7 keeps the game alive and changes nothing for its own awards (Arena Master, unlocked with the guard on: Steam stored it, the guard skipped slot 4294967295, the game played on). Dropping inactive slots as well would skip a task end the game itself makes at startup (slot 0).

## The trainer's two faces

- **KCD1 renders with D3D11**; KCD2 Companion's overlay hooks its swap chain (3 buffers, format 28, 3440×1440) and DirectInput, and draws the F6 window with its tabs, clicks and typing while the game ignores the input; Esc closes it without opening the pause menu.
- **The F6 window reads the language once a session.** After `g_language` changes in a running game, its rows follow and its title and tab names do not until a restart (the overlay's own state, shared with KCD2 Companion).
- **The mod's poller answers in 0.2-0.6 s**; the Items tab, about 120 KB in 40 log entries, in 0.3 s.

- The game minimises when another window takes focus; keys sent to it then reach the front window (Steam). `ShowWindow(SW_RESTORE)` and a click on the window bring it back; `SetForegroundWindow` from a background task is refused.
- **Keys from a remote session reach the game only with a scan code**: `keybd_event(vk, scan, …)` from a process in her desktop session works (Esc skips the intro and holding it skips a cutscene; S moves a dialogue choice down and E picks it); a bare virtual-key press does not. Mouse clicks always pick the highlighted dialogue choice, wherever they land.
